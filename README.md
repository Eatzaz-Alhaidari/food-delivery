## 🍽️ عن المشروع (الفكرة والرؤية)

**سُفرة** هي منصة متكاملة لطلبات الطعام والمطابخ السعودية والمحلية، مصممة بهوية بصرية مميزة مستوحاة من **"طابع ورق المنيو المطبوع"**؛ تجمع بين هدوء التصميم المكتبي التراثي والأداء التقني العصري الفوري (SPA feel) بالاعتماد على **Livewire 3** ودون الحاجة لإعادة تحميل الصفحات.

تلتزم المنصة بدليل تصميم صارم ([DESIGN.md](file:///c:/Users/HP/Desktop/food-delivery/DESIGN.md)):
- **لوحة ألوان من 7 درجات حصرية:** ورق كرافت دافئ خلفي (`#F6F1E9`)، سطح ورقي ناصع (`#FBF8F3`)، حبر مطبوع داكن (`#2B2A27`)، نصوص ثانوية (`#7A756B`)، خطوط حدود رفيعة (`#E2DACB`)، أخضر زيتي رئيسي (`#4F5D45`)، ولون طيني دافئ للخصومات والتنبيهات (`#B5573A`).
- **خالية تماماً من التدرجات اللمعية والظلال العائمة الثقيلة.**
- **طباعة عربية أصيلة:** خط *Noto Kufi Arabic* للعناوين، و*IBM Plex Sans Arabic* للنصوص والقوائم.

## 🛠️ الحزمة التقنية (Tech Stack)

- **الإطار الخلفي:** [Laravel 11](https://laravel.com) (PHP 8.2+)
- **التفاعلية الفورية:** [Livewire 3](https://livewire.laravel.com) + [Alpine.js](https://alpinejs.dev)
- **التنسيق والواجهات:** [Tailwind CSS v3](https://tailwindcss.com) (RTL كامل 100%)
- **الأيقونات:** [Lucide Icons](https://lucide.dev)
- **قواعد البيانات:** MySQL (و SQLite للبيئة التجريبية والاختبارات الآلية)
- **المصادقة والأدوار:** Laravel Breeze مع Middleware مخصص `EnsureRole` و Enum موحد للأدوار

## 👥 الأدوار الثلاثة في المنصة (The 3 Roles)

### 1. العميل (Customer)
- تصفح المطاعم النشطة في الصفحة الرئيسية وقائمة الاستكشاف مع فلترة حية بنوع المطبخ والبحث بالاسم أو الحي والترتيب حسب وقت التجهيز والرسوم.
- استعراض صفحة المطعم مع شريط تصنيفات ثابت أثناء التمرير (`sticky`).
- إضافة الأصناف مع الإضافات الخاصة والكميات وملاحظات الطلب.
- سلة طلبات تفاعلية بدرج جانبي منزلق (`Cart Drawer`) محكومة بقاعدة المطعم الواحد مع خيار تفريغ السلة عند تغيير المطعم.
- صفحة إتمام طلب (`/checkout`) آمنة: إعادة احتساب الأسعار من قاعدة البيانات لحظياً، اختيار أو إضافة عناوين توصيل سريعة، واختيار وسيلة الدفع (نقد عند الاستلام أو دفع إلكتروني تجريبي).
- تطبيق كوبونات الخصم والتحقق منها وحمايتها ضد التخمين (`Rate Limiting`).
- صفحة تتبع حي تفاعلية بشريط تقدم من 5 خطوات هادئة والتحديث كل 5 ثوانٍ تلقائياً.
- إمكانية إلغاء الطلب قبل قبوله من المطعم، وإمكانية إعادة الطلب بضغطة زر واحدة.
- تقييم المطعم من 1 إلى 5 نجوم مع تعليق اختياري بعد استلام الطلب مباشرة.

### 2. صاحب المطعم (Restaurant Owner)
- لوحة تحكم مخصصة على المسار `/restaurant` محمية بصلاحيات وPolicy تمنع أي مطعم من الاطلاع على بيانات مطعم آخر.
- استقبال الطلبات الجديدة فورياً مع تحديث تلقائي كل 10 ثوانٍ (`wire:poll`) وإشعار مرئي عند وصول طلب جديد.
- ترقية حالات الطلب وفق مسار منطقي صارم يمنع القفز أو الرجوع للخلف:
  `قيد الانتظار` $\rightarrow$ `تم القبول` $\rightarrow$ `قيد التجهيز` $\rightarrow$ `جاهز للتوصيل` $\rightarrow$ `في الطريق` $\rightarrow$ `تم التسليم`.
- إمكانية رفض الطلب مع اشتراط إدخال سبب الرفض وتوثيقه للعميل.
- إدارة تصنيفات وقائمة الطعام: إضافة وتعديل وحذف الأصناف، رفع الصور، إدارة الإضافات والأسعار، وتبديل حالة "متوفر / نفد" فوري بدون تحديث الصفحة.
- صفحة بيانات المطعم: تعديل الاسم، الوصف، الحي، وقت التجهيز، الحد الأدنى، رسوم التوصيل، وتبديل حالة "مفتوح / مغلق" لحظياً.

### 3. مدير المنصة (Platform Admin)
- لوحة تحكم شاملة على المسار `/admin` بإحصائيات حية: مبيعات اليوم، إجمالي المبيعات، الطلبات المكتملة، المطاعم النشطة.
- رسم بياني مبسط لتوزيع طلبات آخر 7 أيام ملتزم بلوحة ألوان ورق المنيو.
- إدارة المطاعم: إضافة مطعم جديد مع إنشاء حساب مالكه تلقائياً، تعديل البيانات، وتفعيل أو إيقاف المطعم.
- سجل كافة الطلبات مع فلترة متقدمة بالحالة، المطعم، ونطاق التاريخ مع ترقيم الصفحات.
- تقرير المبيعات وحساب عمولة المنصة التلقائي لكل مطعم بناءً على النسبة المحددة.
- إدارة إعدادات المنصة: تعديل نسبة العمولة المعمول بها عالمياً.
- إدارة الكوبونات: إنشاء كوبونات (نسبة مئوية أو مبلغ ثابت)، تحديد الحد الأدنى وتاريخ الصلاحية والحد الأقصى للاستخدام، وتبديل التفعيل والإيقاف.

## 🚀 طريقة التثبيت والتشغيل المحلي (Setup & Installation)

### المتطلبات الأساسية
- **PHP:** الإصدار 8.2 أو أحدث
- **Composer:** الإصدار 2 أو أحدث
- **Node.js & npm:** الإصدار 18 أو أحدث
- **قاعدة بيانات:** MySQL أو MariaDB

### خطوات التثبيت

1. **استنساخ المستودع والدخول للمجلد:**
   ```bash
   git clone <repo-url> food-delivery
   cd food-delivery
   ```

2. **تثبيت حزم الـ PHP والـ JavaScript:**
   ```bash
   composer install
   npm install
   ```

3. **إعداد ملف البيئة:**
   ```bash
   cp .env.example .env
   php artisan key:generate
   ```

4. **إعداد قاعدة البيانات:**
   عدّل إعدادات الاتصال في ملف `.env`:
   ```env
   DB_CONNECTION=mysql
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_DATABASE=food_delivery
   DB_USERNAME=root
   DB_PASSWORD=
   ```

5. **تشغيل الـ Migrations وبذر البيانات التجريبية الشاملة:**
   ```bash
   php artisan migrate --seed
   php artisan storage:link
   ```

6. **بناء أصول الواجهة:**
   ```bash
   npm run build
   # أو أثناء التطوير: npm run dev
   ```

7. **تشغيل خادم التطوير المحلي:**
   ```bash
   php artisan serve
   ```
   افتح المتصفح وتوجه إلى: `http://localhost:8000`

## 🧪 تشغيل الاختبارات الآلية (Testing Suite)

يحتوي المشروع على حزمة اختبارات شاملة تغطي مسارات الطلب وصلاحيات الأدوار وقواعد انتقال الحالات وصحة جميع الصفحات:

```bash
php artisan test
```

### ملخص تغطية الاختبارات (42 اختباراً ناجحاً بنسبة 100%):
- **`PageHealthTest`:** فحص استجابة كافة صفحات الموقع العامة وصفحات العميل ولوحة المطعم ولوحة المدير ومسارات التخزين والتأكد من خلوها من أي أخطاء (200 OK).
- **`RolePermissionsTest`:** التحقق من عزل الصلاحيات وحماية مسارات `/admin` و `/restaurant` ومنع وصول العملاء والزوار غير المصرح لهم (403 Forbidden).
- **`OrderStatusTransitionTest`:** اختبار الانتقال المتسلسل لحالات الطلب، ومنع القفز المباشر أو الرجوع للخلف، واشتراط سبب الرفض، وتوثيق سجل التغييرات `order_status_logs`.
- **`OrderCreationTest`:** التحقق من إنشاء الطلبات المالية، تطبيق وتحديث عداد الكوبونات، ومنع تكرار تقييم الطلب المسلّم.

## 🚀 دليل الرفع إلى GitHub واستضافة Hostinger (Deployment Guide)

### أولاً: الرفع إلى مستودع GitHub

المشروع جاهز ومُجهّز بملفات البناء وملفات التنسيق والصور:

```bash
# 1. تهيئة مستودع Git محلياً
git init

# 2. إضافة كافة الملفات (ملفات البناء public/build والصور التجريبية مضمنة تلقائياً)
git add .

# 3. حفظ الالتزام
git commit -m "feat: complete Sufra food delivery platform with full features, tests and design"

# 4. تسمية الفرع الرئيسي
git branch -M main

# 5. ربط المستودع البعيد (استبدل الرابط برابط مستودعك على GitHub)
git remote add origin https://github.com/USERNAME/food-delivery.git

# 6. الرفع إلى GitHub
git push -u origin main
```

### ثانياً: النشر على استضافة Hostinger

المشروع مُهيأ ليعمل بسلاسة على استضافات Hostinger المشتركة والسحابية:

#### الخطوة 1: إعداد قاعدة البيانات في Hostinger
1. ادخل إلى لوحة تحكم **hPanel** في Hostinger.
2. توجّه إلى قسم **Databases (قواعد البيانات)** ثم **MySQL Databases**.
3. أنشئ قاعدة بيانات جديدة مع اسم مستخدم وكلمة مرور قويين، واحتفظ بالبيانات.

#### الخطوة 2: رفع المشروع (طريقتان)

* **الطريقة أ (عبر ميزة Git في Hostinger - الموصى بها):**
  1. في لوحة hPanel، افتح **Git**.
  2. أدخل رابط مستودع GitHub والفرع `main`.
  3. اختر مجلد التثبيت واضغط **Create & Deploy**.

* **الطريقة ب (عبر مدير الملفات File Manager أو FTP):**
  1. اضغط مجلد المشروع في ملف `zip`.
  2. ارفعه إلى المجلد الرئيسي في الاستضافة ثم قم بفكه.
  3. بفضل ملف `.htaccess` الذي أعددناه في جذر المشروع، يتم تلقائياً توجيه الزوار إلى مجلد `public` وحماية ملف `.env` دون الحاجة لتغيير هيكلة Laravel.

#### الخطوة 3: إعداد ملف البيئة `.env`
1. أنشئ ملف `.env` في المجلد الرئيسي (أو انسخ من `.env.example`).
2. اضبط القيم التالية:
   ```env
   APP_NAME="سُفرة"
   APP_ENV=production
   APP_KEY=base64:... (يمكنك نسخه من جهازك أو تشغيل php artisan key:generate)
   APP_DEBUG=false
   APP_URL=https://your-domain.com

   DB_CONNECTION=mysql
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_DATABASE=اسم_قاعدة_البيانات_في_هوسترنجر
   DB_USERNAME=اسم_المستخدم_في_هوسترنجر
   DB_PASSWORD=كلمة_المرور
   ```

#### الخطوة 4: تشغيل الأوامر النهائية (عبر SSH أو Terminal في hPanel)
```bash
# تثبيت الحزم (إن لم تكن مرفوعة مسبقاً)
composer install --no-dev --optimize-autoloader

# إنشاء الجداول وتعبئة المطاعم والأصناف التجريبية
php artisan migrate --force --seed

# ربط ملفات التخزين
php artisan storage:link

# تحسين الأداء وتسريع الكاش
php artisan config:cache
php artisan route:cache
php artisan view:cache
```

> [!TIP]
> مجلد أصول الواجهة `public/build` ومجلد الصور التجريبية `public/demo` مضمّنة في المستودع مسبقاً، لذا لن تحتاج إلى تشغيل `npm run build` على خادم Hostinger!
